# Release preparation

Reviewed 14 October 2026. This is a personal beta, not an accepted production release. APK assembly and automated tests do not establish hardware encryption, real-bank coverage, speech accuracy or store-policy acceptance.

## Reproducible delivery verification

Use Node 24, JDK 17, Android SDK/build tools 36 and the committed lockfile. Start with `npm ci`, `npm run test:regression` and `npx expo-doctor`. Prebuild with the intended profile before assembling: ordinary prebuild selects the personal package; `KANAKKU_BUILD_PROFILE=e2e` selects the isolated sample-test package. Never publish or install a test-package APK as the personal build.

```sh
node scripts/verify-apk.mjs artifacts/kanakku-personal-beta.apk
node scripts/verify-apk.mjs artifacts/kanakku-e2e.apk --e2e
node scripts/verify-apk.mjs path/to/production.apk --production
```

Set `ANDROID_HOME` and `JAVA_HOME` first. Verification is read-only. It checks the expected package, Android 12 minimum, arm64 ABI, successful APK signature verification, disabled backups, non-debuggable manifest, bundled MiniLM/Whisper hashes and the three voice native libraries. The production flag rejects the Android Debug certificate; it does **not** establish certificate ownership, production acceptance or zero vulnerabilities. Record the actual expected signing certificate fingerprint externally and compare it before delivery. Refresh the build manifest/hash after a rebuild.

Current personal APK passes the read-only verification and uses development signing. Production verification deliberately fails for that artifact. No signing credentials were generated or changed.

## Production signing and distribution

Create an owner-controlled signing/upload key only when distribution is intended. Keep keystore passwords and key files outside source control and share them through a secret manager. Preserve a recoverable private backup: updates require a compatible signing identity. Configure signing durably through the supported Expo/build process; editing only generated `android/` files loses configuration at prebuild. Do not assume a Gradle task named `assembleRelease` uses a production key. See [Android signing](https://developer.android.com/studio/publish/app-signing) and [Expo local credentials](https://docs.expo.dev/app-signing/local-credentials/).

No shared Brave credential belongs in an APK, environment bundle or browser storage. Personal BYOK remains Settings-based with native Keystore encryption. Shared search access needs a separately deployed backend with authentication, quotas and provider budget controls.

Before public distribution: verify provider/model licenses, Android SMS permission eligibility, privacy/data safety declarations, signed upgrade preservation, restore/deletion behavior, physical-device acceptance and remaining dependency advisories. This review does not approve Play Store submission or modify any account.

## Accessibility and error-state evidence

`tests/e2e/accessibility.spec.ts` adds six independent journeys, each on phone/desktop browser sizes. Validated: arrow/Home/End/wrapping tab navigation with one focus stop; selected state; named filter dialog with initial close focus, keyboard containment and Escape/focus return; private accessible transaction labels while amounts are hidden; 44px primary navigation/search targets; simulated 200% computed browser text with search, invalid-filter recovery and navigation; empty-history setup.

The audit demonstrated missing tab keyboard handling and an unnamed modal. TabBar now supplies roving keyboard focus and native selected state; Sheet names the modal and focuses its close button on web. The initial accessibility + launch + ledger suite passed **42 browser runs**. A later combined review/accessibility/avatar suite passed **52 browser runs** after the review-sheet changes; TypeScript also passes. Test logs: `/tmp/kanakku-accessibility-green.log` and `/tmp/kanakku-review-avatar-final.log`. This focused result is separate from final full-suite and rebuilt-APK acceptance.

`tests/e2e/review-accessibility.spec.ts` additionally verifies initial Close focus, forward/backward containment, Escape discarding edits, return to the opener, queue progression and a navigation fallback when the opener disappears. The review sheet observes actual portal mounting before installing focus containment. Seeded inputs preserve fast typed edits without asynchronous portal state echoes overwriting later keystrokes; voice replacement explicitly reseeds the note.

These are journey checks, not full WCAG acceptance. The text-resize test doubles computed fonts on text-bearing browser nodes; it does not prove Android system font scaling, TalkBack order, every possible dialog state, contrast at every state or overlay accessibility. Test those on emulator/phone and retain physical-device TalkBack/voice/battery acceptance as open.
